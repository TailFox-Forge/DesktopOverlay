# DesktopOverlay 요구사항

## 개요

사용자가 선택한 이미지 또는 GIF를 데스크톱 화면 위에 배경 없이 띄운다.

일반 창 조작 없이 트레이 아이콘에서 제어할 수 있어야 한다.

1차 대상은 윈도우 데스크톱이다.

게임 방송 중 화면 한쪽에 캐릭터를 상시 표시하는 용도를 기준으로 설계했다.

## 2. 배경 제거

배경 제거 방식은 **로컬 처리**로 확정했다.

외부 모델이나 API를 쓰지 않는다.

단순 색상키는 "배경색과 같은 픽셀을 지운다"는 방식이라, 피사체에 배경과 같은 색이 있으면 그 부분까지 뚫린다.

흰 배경 + 흰 머리 캐릭터에서 얼굴까지 사라지는 것을 실제로 확인했다.

따라서 색이 아니라 **피사체의 외곽선을 경계로** 삼는다.

| 항목 | 상태 | 비고 |
|---|---|---|
| 배경색 자동 추출 | 완료 | 네 모서리에서 최빈색 |
| 배경색 수동 지정 | 완료 | |
| 외곽선 기준 제거 | 완료 | 가장자리에서 flood fill, 외곽선에서 정지 |

| 테두리 배경색 물빠짐 제거 | 완료 | |
| 원본 / 제거 결과 전환 | 완료 | 트레이 메뉴 → 배경 제거 |
| 제거 강도 · 외곽선 민감도 · 가장자리 부드럽게 | 완료 | |
| 처리 실패 시 원본 유지 및 알림 | 완료 | 읽기 실패 시 오류 대화상자 |
| 대형 이미지/GIF 처리 중 UI 응답 유지 | 완료 | 로딩/배경 제거를 worker thread에서 수행 |
| 외곽선 바깥 영역 탐색 최적화 | 완료 | 행/열 단위 numpy sweep 방식 |

### 알려진 한계

- 배경과 피사체 사이에 외곽선이 없고 색까지 같으면 경계를 찾지 못한다.
- 흰 · 검 · 회색 배경에서는 피사체 고유색과 구분할 수 없으므로 둘러싸인 배경을 제거하지 않는다.
- 선화 · 일러스트 · 스티커를 대상으로 하며, 외곽선이 없는 사진에는 적합하지 않다.

창이 클릭을 통과시키는 동안에는 창을 직접 조작할 수 없으므로, 트레이 메뉴가 유일한 제어 수단이 된다.

따라서 모든 설정이 트레이에서 접근 가능해야 한다.

업데이트 확인은 GitHub 최신 릴리스를 백그라운드에서 조회한다.

현재 실행 버전보다 높은 릴리스가 있으면 트레이 아이콘 우상단에 빨간점을 표시하고, 메뉴에서 릴리스 페이지를 열 수 있어야 한다.

### 단축키 정책

전역 단축키는 OS 전체의 입력을 가로채므로, 잘못 등록하면 사용자가 키보드로 복구할 수 없는 상태에 빠진다.

따라서 아래 제한을 둔다.

- 수식어(Ctrl/Alt/Shift/Win) 없는 단독키는 원칙적으로 거부한다.
- 예외로 넘버패드 `Num0`~`Num9` 만 단독 등록을 허용한다. 일반 숫자와 분리해 인식한다.
- `Ctrl+Alt+Delete`, `Alt+Tab`, `Ctrl+Esc`, `Ctrl+Shift+Esc` 같은 Windows 예약 조합은 거부한다.
- 수식어가 붙은 `Ctrl+Delete`, `Ctrl+Backspace`, `Ctrl+Tab`, `Ctrl+Shift+Delete` 는 허용한다. 예약 조합이 아니기 때문이다.
- 서로 다른 기능에 같은 단축키를 넣으면 기존 기능의 단축키를 해제하고 새 기능에 배정한다.
- 보이기/숨기기 토글과 보이기·숨기기 개별 단축키는 동시에 쓰지 않는다. 한쪽을 등록하면 반대쪽을 해제한다.

판정 로직은 캡처 UI 와 `config.json` 로드 경로가 **같은 함수를 공유해야 한다.**

두 경로가 갈라지면 설정 파일을 직접 편집해 제한을 우회할 수 있다.

### 복구 경로

전역 단축키가 입력을 가로채 키보드를 쓸 수 없게 되어도 마우스만으로 복구할 수 있어야 한다.

트레이 메뉴의 **단축키 비활성화** 가 그 경로다.

## 8. 배포

| 항목 | 상태 | 비고 |
|---|---|---|
| 단일 exe 빌드 | 완료 | PyInstaller onefile. `build.bat` |
| 파이썬 미설치 시 안내 | 완료 | `Desktop_Overlay_Start.bat` 이 설치 페이지로 안내 |
| 라이브러리 자동 설치 | 완료 | 같은 배치 파일에서 처리 |
| 설정을 exe 옆에 저장 | 완료 | onefile 은 `__file__` 이 임시 폴더라 `sys.executable` 기준 |
| 빌드 도구 버전 고정 | 완료 | `requirements-build.txt` |
| 자동 테스트 | 완료 | pytest + GitHub Actions |
| 태그 릴리즈 자동 빌드 | 완료 | Windows runner에서 exe와 SHA256 생성 |

exe 는 저장소에 커밋하지 않는다.

용량이 50MB를 넘으므로 GitHub Releases 로 배포한다.

### 릴리스 절차

GitHub 가 자동으로 제공하는 **Source code (zip/tar.gz)** 는 태그가 가리키는 커밋으로 고정된다.

따라서 태그를 찍은 뒤에 문서를 갱신하면, 그 릴리스의 source archive 안 문서가 이전 버전을 안내하게 된다.

이를 막기 위해 다음 순서를 지킨다.

1. 코드 변경을 커밋한다.
2. `APP_VERSION` 을 새 버전으로 올린다.
3. README 의 **버전별 변경 내역** 에 해당 버전 항목을 추가한다.
4. 위 내용을 커밋한 뒤 그 커밋에 태그를 찍는다.
5. 태그를 푸시하면 릴리스 워크플로가 빌드와 게시를 수행한다.

**SHA256 은 README 에 적지 않는다.**

해시는 빌드 이후에만 알 수 있으므로 태그 시점의 문서에 담을 수 없다.

릴리스 노트에만 기재하고, README 는 항상 `releases/latest` 를 가리킨다.

릴리스 워크플로는 빌드 전에 다음을 검증한다.

- 태그가 `vX.Y.Z` 형식인가
- `APP_VERSION` 이 태그 이름과 일치하는가
- README 의 버전별 변경 내역에 해당 태그 항목이 있는가

셋 중 하나라도 어긋나면 빌드를 중단한다.

## 기술 스택

Python 3.8 이상, PyQt5, Pillow, numpy.

클릭 통과는 `WM_NCHITTEST`에 `HTTRANSPARENT`를 반환하는 방식으로 구현한다.

`WS_EX_TRANSPARENT` 확장 스타일은 반투명 창의 렌더링을 깨뜨리는 것을 확인했으므로 쓰지 않는다.

이 의존성 때문에 현재 윈도우 전용이다.
